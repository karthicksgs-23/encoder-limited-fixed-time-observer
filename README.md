# Encoder-limited fixed-time observer simulations

Python simulation code for adaptive fuzzy output-feedback control of a constrained robot arm. A fixed-time observer estimates joint velocity from a quantised encoder. The code covers a single-link arm and a coupled two-link arm, with Monte Carlo tests over encoder resolution, sensor noise, observer gain and torque limits.

## Files

| Script | Purpose | Output |
|---|---|---|
| `arm_margin_test.py` | Core single-link simulator: plant, encoder, fixed-time observer, fuzzy approximator, command filter, controller | `results/pilot.json` |
| `run_all.py` | Test 1: fixed margin test and exploratory sweep | `results/all_results.json` |
| `run_diagnostic.py` | Test 1: bounded diagnostic | `results/diagnostic.json` |
| `test2_resolution.py` | Test 2: encoder resolution sweep (10–16 bit) | `results/test2.json` |
| `test3_realistic.py` | Test 3: 1 kHz digital implementation, sensors S1–S3, five designs | `results/test3.json` |
| `test3b_followup.py` | Test 3b: torque dependence, "no cancel" design, clearance sensitivity | `results/test3b.json` |
| `test4_rule_check.py` | Test 4: check of the gain-ceiling rule | `results/test4.json` |
| `test5_confirm.py` | Test 5: confirmation on unseen seeds 20–24, with time responses | `results/test5.json`, `results/traces.json` |
| `test6_settling.py` | Test 6: observer settling time versus gain | `results/test6.json` |
| `test7_two_link.py` | Test 7: coupled two-link arm, decentralised design | `results/test7.json`, `results/traces7.json` |
| `test8_diagnose.py` | Test 8: diagnosis of two-link violations | `results/test8.json` |
| `test9_fix.py` | Test 9: start-up clearance on new seeds 40–44 | `results/test9.json` |
| `make_figures.py` | Plots from the saved results | `figures/*.png` |
| `analysis/test3_summary.py`, `analysis/test3b_summary.py` | Text summaries of Tests 3 and 3b | stdout |

Tests 2–9 import `arm_margin_test.py`; Tests 3b, 4 and 5 also import `test3_realistic.py`, and Tests 8 and 9 import `test7_two_link.py`. Run every script **from the repository root**, because some paths are relative to it.

## Setup

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scriptsctivate
pip install -r requirements.txt
```

Tested with Python 3.11.9, NumPy 2.4.6, SciPy 1.17.1 and Matplotlib 3.11.2 on Windows 11 (CPU only).

## Run

Plots from the saved results (about a minute):

```bash
python make_figures.py
```

Quick check that the simulator runs (3 runs per case, about 30 s):

```bash
python arm_margin_test.py --runs 3 --tag smoke
```

All tests in order. Monte Carlo tests use `multiprocessing`; a full rerun takes several hours on a desktop CPU.

```bash
bash run_tests.sh
```

Scenario seeds are fixed inside each script, and each script states its pass/fail criteria in its docstring. Reruns on the same NumPy version should reproduce the saved JSON files.

## Data

All data in `results/` are generated by these scripts. No external dataset is used. `results/RESULTS.md` summarises every test.
